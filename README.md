# Расчёт заказов по артикулам и дням

Скрипт читает `sales.csv` и собирает отчёт `daily_by_sku.csv`: сколько заказов было по каждому артикулу в каждый день и какая по ним выручка.

## Что считается

- `orders` — все заказы за день по артикулу, включая отменённые.
- `revenue` — только доставленные заказы: `quantity × price`.
- Если строка заказа встретилась дважды, заказ считается один раз.
- Написание статусов не важно: `Delivered`, `DELIVERED`, `canceled` и другие варианты приводятся к одному виду.

## Проблемы в данных

- **Дубли.** 60 строк были полными копиями других строк. Оставил по одной копии: 13 858 строк превратились в 13 798 заказов.
- **Статусы.** Встречались `Delivered`, `DELIVERED`, `delivered ` с пробелом, `canceled` и другие варианты. Привёл их к `delivered` и `cancelled`; `canceled` считается отменой.
- **Пустой** **`quantity`.** В 4 отменённых заказах не было количества. Они остались в числе заказов, но не попали в выручку. Если количество пустое у доставленного заказа, расчёт останавливается с ошибкой.

Других проблем не было: даты, цены, количества и артикулы корректны.

## Как запустить

Нужен Python 3. Сторонние библиотеки не используются, `pip install` не нужен. Проверено на Python 3.10.11.

Откройте терминал в папке проекта и выполните:

```
python calculate.py
```

Если команда `python` не найдена, на Windows можно попробовать:

```
py calculate.py
```

Скрипт не требует аргументов: `sales.csv` он ищет рядом с собой.

Или

Откройте Visual Studio Code (возможно также открыть Visual studio, Cursor и другие редакторы кода), кодовый редактор самостоятельно предложит нужную версию python.

## Где результат

В папке проекта появится файл `daily_by_sku.csv`.

| Колонка | Что внутри |
| --- | --- |
| `sku` | артикул |
| `order_date` | дата заказа в формате `ГГГГ-ММ-ДД` |
| `orders` | число заказов, включая отменённые |
| `revenue` | выручка по доставленным заказам |

Строки отсортированы по `sku`, затем по дате.

## Файлы

- `sales.csv` — исходная выгрузка;
- `calculate.py` — скрипт расчёта;

## Проверка

Итог: 13 798 уникальных заказов и 10 276 540 выручки. Ручной пересчёт в Excel совпал с отчётом.

Если открываете `daily_by_sku.csv` в Excel, лучше использовать **Данные → Из текста/CSV** и выбирать разделитель «запятая»: в русской локализации Excel не всегда разбивает такой файл по столбцам при двойном клике.

Какие проблемы нашли в данных и как с ними поступили

Проблемы были такие:

### 1. Дубли

В файле было **13 858 строк**, но только **13 798 уникальных заказов**. Нашлись 60 групп полных дублей — по две одинаковые строки с одним и тем же `order_id`, датой, SKU, количеством, ценой и статусом.

**Как поступили:** перед расчётом удалили полные дубли строк. В этих данных это эквивалентно дедупликации по `order_id`, потому что у каждого заказа ровно одна уникальная строка. Исходный `sales.csv` не меняли — чистка происходит только при расчёте.

Среди дублей были и доставленные, и отменённые заказы, поэтому без дедупликации завысились бы и `orders`, и `revenue`.

### 2. Разное написание статусов

Вместо двух статусов в файле было **8 вариантов**:

- `delivered`
- `delivered `— с пробелом в конце
- `Delivered`
- `DELIVERED`
- `cancelled`
- `Cancelled`
- `CANCELLED`
- `canceled`

**Как поступили:** у статуса убрали пробелы, привели регистр к нижнему, а `canceled` заменили на `cancelled` — это одно и то же. В расчёте остаются только `delivered` и `cancelled`. Если встретится неизвестный статус, скрипт остановится с ошибкой, чтобы не посчитать выручку неправильно.

После удаления дублей получилось **12 047 delivered** и **1 751 cancelled**.

### 3. Пустой `quantity`

Нашлись **4 строки без количества**:

- `1012637`
- `1010495`
- `1013303`
- `1013394`

Все четыре — отменённые заказы.

**Как поступили:** не стали придумывать им количество. В `orders` они вошли, потому что это заказы, а в `revenue` не попали, потому что не `delivered`. Если бы пустое количество оказалось у доставленного заказа, скрипт бы упал с ошибкой и показал `order_id` — молча подставлять 0 нельзя.

### 

Что специально **не** делали:

- не удаляли отменённые заказы — они входят в `orders`;
- не подставляли `quantity = 0`;
- не меняли исходный `sales.csv`.

Одно важное допущение: **один заказ = одна строка**. Нейросеть проверила: после дедупликации у каждого из 13 798 `order_id` ровно одна уникальная строка. Если бы заказ мог состоять из нескольких строк с разными SKU, логику пришлось бы менять.

Итог после обработки: **13 798 заказов**, **12 047 доставленных**, выручка **10 276 540**. Это совпало с независимым пересчётом через PowerShell и с ручной проверкой в Excel.
